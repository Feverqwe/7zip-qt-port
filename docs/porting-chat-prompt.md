# Сообщение для нового чата портирования

Скопируйте текст ниже. Для конкретного шага замените предложение о выборе ID
на «Выполни шаг …». Текущие статусы, результаты проверок и handoff читаются
из документов и памяти; их не нужно переносить в каждый стартовый запрос.

```text
Продолжай портирование Sevenzip Desktop.

Прочитай AGENTS.md, docs/porting-checklist.md и нужные разделы
docs/porting-plan.md. Начни с .codex/memory/README.md, если он есть,
и только relevant notes. Проверь git status, HEAD, текущий код и
относящиеся к шагу audit/parity. Сохрани чужие изменения.

Выбери первый незавершённый доступный ID по приоритетам и фактическим
dependencies/capabilities из чеклиста. Назови ID и конкретный результат.
Выполни целый интегрированный компонент или сценарий с consumers и UX,
следуя правилам source port, проверок и размера итерации из AGENTS.md
и плана. Обязательные UX-коррекции учитывай по docs/ux-port-audit.md.
Блокировка одной функции не останавливает другой доступный scope;
сохраняй исторические ID и evidence по правилам плана.

По последним коммитам и handoff укрупни оставшиеся итерации: объединяй
связанные source bodies, consumers, UX, ошибки, отмену и регрессии в законченный
сценарий. Не делай отдельную итерацию или коммит на каждый helper, guard,
ветку ошибки или тест. Историю Git и прежние evidence сохраняй.

Не создавай и не подключай новые диски на виртуалках. При нехватке места
удаляй старые данные Sevenzip Desktop: неактивные snapshots, сборки и временные
файлы по retention и проверкам из docs/hyperv-runners.md. Такая очистка разрешена
без повторного подтверждения; сохраняй активные запуски, три последних запуска
в каждом workspace, нужные evidence, toolchains и чужие данные. Проверь свободное
место до и после очистки. Не заменяй очистку расширением дисков.

Обнови статус своего шага в чеклисте, provenance в audit, изменившиеся
claims профильных документов и полезный local handoff. Не дублируй
счётчики и логи проверок в стартовом запросе или README.
Каждую завершённую крупную итерацию коммить отдельно после проверок,
только свои файлы/hunks. Push, PR, release и изменения upstream
в это поручение не входят.

В конце сообщи результат, copied/adapted scope, текущие checks и ОС,
оставшиеся ограничения, local commit и следующий доступный ID.
Продолжай доступную работу без промежуточных подтверждений.
```

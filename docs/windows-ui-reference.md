# Сбор размеров оригинального 7zFM на Windows

Скрипт `scripts/capture-7zfm-reference.ps1` снимает геометрию **официального
Windows 7-Zip**, а не нашего Qt-приложения. Нужны Windows 10 версии 1703 или
новее / Windows 11 и встроенный Windows PowerShell 5.1 либо PowerShell 7.
Права администратора, Python, Visual Studio и сборка проекта не нужны.
Можно скопировать только этот PS1 на Windows.

## Все шаблоны автоматически, без открытия через меню

В PowerShell из папки со скриптом сначала можно проверить сборщик:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\capture-7zfm-reference.ps1 -SelfTest
```

Это создаёт одноразовое окно с известными координатами, статической подписью,
полем ввода и скрытой кнопкой. Проверяются ID, родительские связи, размеры,
состояние видимости, исключение введённого текста и запись/чтение JSON.
При неудаче сборщик завершится с ошибкой; успешный SelfTest не проверяет
все шаблоны EXE, скриншоты или runtime 7zFM.

Затем выполнить сбор:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\capture-7zfm-reference.ps1 -TemplatesFrom "C:\Program Files\7-Zip\7zFM.exe" -OutputDirectory .\templates-100 -State resource-template -Screenshots
```

Скрипт переберёт **все RT_DIALOG в указанном EXE**, создаст каждую форму
стандартными Win32-контролами, сохранит JSON/PNG и закроет её. Не нажимать
кнопки и не перекрывать появляющиеся окна во время сбора. В итоговом
`templates-summary-*.json` будут количество успешных снимков и ошибки
по каждому непостроенному шаблону; при ошибках скрипт завершится с ошибкой.
В каждом снимке есть `resourceName`, например `#123`, и
`captureKind: resource-template`. Повторить при масштабе 150% в другой папке.
Если нижняя часть страницы настроек на PNG показывает другое окно или рабочий
стол, это обрезка её родительским окном стенда; JSON-геометрия остаётся
доступной. После обновления скрипта повторить серию PNG при том же масштабе.
Для диалогов отдельного GUI-процесса повторить команду с `7zG.exe` и
отдельной выходной папкой.

EXE [загружается как ресурсные данные](https://learn.microsoft.com/en-us/windows/win32/intl/loading-a-win32-pe-resource-module),
его код не выполняется. Это стенд
для **базовой геометрии шаблонов**, без компилятора: не нужно добираться до
редких ошибок или выполнять операции с архивами. Формы создаёт PowerShell
под Per Monitor V2, поэтому DPI-контекст может отличаться от настоящего 7zFM.
Стенд также не активирует манифест EXE: версия/тема Common Controls может
отличаться от приложения. Его PNG не доказывает совпадение оформления.
Используется выбранная Windows ресурсная локаль; `-Language` — только метка,
не переключатель языка. Переводы 7-Zip из `.lng` не применяются.

Размеры и тексты, которые оригинальные OnInit/OnSize изменяют программно,
сборка страниц в реальное окно настроек, заполнение списков и условные состояния этим
режимом не воспроизводятся. Поэтому для реально используемых диалогов нужен
дополнительный runtime-снимок по F8, описанный ниже. Компиляция каждого `.rc`
отдельно тоже дала бы лишь шаблон; исполнение настоящих C++-классов потребует
отдельного C++-стенда с зависимостями и сценариями инициализации.

## Запуск

1. Установить официальный 7-Zip с [7-zip.org](https://www.7-zip.org/).
   Для сравнения с исходниками желательно использовать соответствующую им
   версию: текущая ресурсная база проекта — commit
   `0766b733fe3e06dd2a7f9a3cfbf2108ac73abd17`. Версия установленного EXE сама
   по себе не доказывает совпадение с этим commit. Другую версию тоже можно
   снять, но её отличия потребуют отдельной проверки.
2. Поставить масштаб экрана 100%, открыть `C:\Program Files\7-Zip\7zFM.exe`.
   Использовать отдельную тестовую папку с несколькими файлами и архивом,
   включая файл с длинным именем и пробелами. Выбрать один язык интерфейса.
3. В PowerShell из папки, куда скопирован скрипт, выполнить:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\capture-7zfm-reference.ps1 -OutputDirectory .\reference-100-ru -Language ru -State initial -Screenshots
   ```

   `ExecutionPolicy Bypass` действует только на этот процесс. Если Windows
   блокирует скачанный файл, после проверки его содержимого выполнить
   `Unblock-File .\capture-7zfm-reference.ps1`. Корпоративные политики скрипт
   не обходит. Запускать 7-Zip и PowerShell с одинаковыми обычными правами.
4. Открыть нужное окно/диалог в 7-Zip и, оставив его активным, нажать **F8**.
   Каждое нажатие создаёт отдельный JSON и, с `-Screenshots`, PNG. Диалог
   закрывать не нужно. F8 только опрашивается: скрипт не поглощает клавишу
   и не меняет окна/данные приложения. Консоль остановить через Ctrl+C.
5. Повторить для остальных диалогов. Для изменённых размеров/состояний
   перезапустить скрипт с `-State resized` или описательным значением,
   например `extract-overwrite-ask`. Начальный размер снимать до растягивания.
6. Поставить масштаб 150%, закрыть и вновь открыть 7-Zip, повторить сбор
   в `reference-150-ru`. Держать окно целиком на одном мониторе. Масштаб 125%
   и английский интерфейс полезны как дополнительные отдельные серии.

Без `-Screenshots` сохраняется только геометрия. При PNG окно должно быть
полностью видно, без перекрывающих окон: это снимок экранной области, а не
рендер невидимого окна. Не снимать реальные архивы, пароли или личные пути.
JSON исключает значения полей ввода, combo/list/tree, но заголовки окна и
статические подписи могут содержать пути. PNG содержит всё видимое, включая
пароль при включённом «Показать пароль». Проверить файлы перед передачей.

Для автоматизации в активной тестовой Windows-сессии можно снять конкретное
окно один раз через `-WindowHandle <decimal HWND>`. Скрипт проверяет, что HWND
принадлежит `7zFM` или `7zG`; он не открывает диалог, не меняет выделение и
не нажимает кнопки. При снимке реального внешнего процесса `dialogBaseUnitsPx`
равно `null`: `MapDialogRect` на чужом HWND вызвал access violation на
Windows 11 10.0.26300. Измерения окон/контролов в физических пикселях сохраняются.
Единицы диалога доступны только для собственного resource-template стенда;
не выводим их из предположения о шрифте.

## Что снять

Для дополнительной проверки настоящего runtime достаточно этой серии.
В режиме F8 окна открывать вручную; скрипт не выполняет архивные операции.

| Окно / диалог | Как открыть и какие состояния снять |
| --- | --- |
| Главное окно | Сразу после запуска; затем уменьшенное окно; при возможности режим двух панелей |
| Добавить в архив | Выделить тестовый файл → Добавить; форматы 7z и zip отдельно |
| Извлечь | Выделить тестовый архив → Извлечь; дополнительные опции в разных состояниях |
| Копировать / Переместить | Выделить тестовый файл → F5 / F6; исходный и уменьшенный размер |
| Новая папка | F7; снять и отменить |
| Разбить файл | Меню Файл → Разбить файл; снять и отменить |
| Объединить файлы | Выделить тестовый `.001` → Объединить файлы; снять и отменить |
| Свойства | Выделить файл → Alt+Enter; исходный и уменьшенный размер |
| Настройки | Сервис → Настройки; каждая вкладка отдельно |
| Пароль | Открыть тестовый архив с зашифрованными именами; пустое поле, показ выключен |
| Подтверждение замены | Извлечение тестового архива в папку с одноимённым тестовым файлом; снять и отменить |
| Прогресс | Достаточно длительная операция на тестовых файлах; раскрытые/скрытые подробности, если доступны |

Нельзя считать отсутствующий диалог проверенным. Редкие формы (например,
предупреждение о памяти) добавляются по мере доступности воспроизводимого
сценария. Для уточнения состояния можно положить рядом `notes.txt` с именем
JSON, действием, языком, масштабом и тем, изменялся ли размер вручную.

## Формат и использование

Передать обе папки целиком или ZIP и положить, например, в
`build/windows-ui-reference/` этого checkout. Это локальные артефакты, которые
не следует автоматически коммитить. В каждой записи есть версия и SHA-256
EXE, время, язык/состояние, DPI и awareness исходного окна, размеры внешнего
окна, видимой DWM-рамки и клиентской области, а также плоский список всех
дочерних HWND, включая невидимые. Связи задаются `parentHandle`; HWND действуют
только внутри конкретного снимка. `controlId` сопоставляется с числовыми
Win32 ID из исходных ресурсов; ID не всегда уникальны.

Координаты записываются в физических пикселях под DPI-контекстом сборщика
Per Monitor V2. `boundsRootClientPx` отсчитываются от клиентского начала
корневого окна; `windowBoundsScreenPx` — от начала рабочего стола (возможны
отрицательные координаты). Клиентские размеры исключают рамку/заголовок.
`visibleFrameBoundsScreenPx` отдельно учитывает видимую рамку: обычный
GetWindowRect может включать невидимые границы изменения размера.
См. [документацию Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowrect).

`dialogBaseUnitsPx` — результат MapDialogRect для `[0,0,4,8]` только у
`#32770`: это база перевода диалоговых единиц ресурсов, не размер диалога.
`font` содержит исходный LOGFONT, если контрол отдаёт WM_GETFONT; высота
шрифта остаётся в его логических единицах, без пересчёта в физические пиксели.
Null не означает отсутствие текста. `dpiAwareness`: 0 unaware, 1 system aware, 2 per monitor;
`dpi` принадлежит исходному окну, поэтому для unaware-приложений он не
обязательно равен масштабу монитора. Записывать масштаб в имени серии/notes.

Сборщик не читает строки списков, меню, элементы вкладок, owner-drawn детали,
порядок Tab и фактическое перекрытие контролов. Снимки таких деталей помогают
проверить PNG вручную. Полученные данные — дополнительный Windows runtime
эталон: они не заменяют закреплённые RC-ресурсы, аудит исходников и Qt-тесты.
Автоматический comparator из `check_ui_parity.py` пока принимает Qt-отчёты,
а не этот Windows JSON. Прямое сравнение с native Qt JSON выполняет
[runtime comparator для агента](ui-runtime-comparison.md).

Скрипт требует проверки на настоящей Windows; его выполнение на macOS
не подтверждает корректность Win32/PInvoke или визуальную точность.

## Pinned runtime System menu reference

`scripts/check-native-menu-reference.sh` проверяет affected File/System popup
на настроенном Windows x64 runner с активным desktop
([local configuration](runner-configuration.md)):

```bash
python3 scripts/hyperv-runner.py run windows --interactive -- scripts/check-native-menu-reference.sh
```

Сначала `build-windows-reference.ps1` извлекает закреплённый upstream commit
в отдельный snapshot и собирает оригинальные FileManager makefile/resources
через MSVC/nmake. Sibling checkout остаётся read-only. Entry wrapper включает
полный исходный FM.cpp с alias имени WinMain. Два product-path macro в
RegistryUtils.cpp/ViewSettings.cpp заменяются уникальным private HKCU path;
это сохраняет исходные function bodies и registry view системных providers.
Fixture отказывает при существующем key, отмечает owner PID и удаляет только
свой key. Original7zFM normal exit и cleanup проверяются тестом; emergency
cleanup требует совпадающий marker. Официальная регистрация не меняется.

`build/windows-reference/reference.json` содержит source repository/full
revision, hashes оригинальных и adapted files, wrapper и executable. Только
при наличии этого manifest CMake регистрирует `native_rendered_system_menu`.
Тест открывает настоящий native7zFM File/System menu на disposable Unicode
файле и сравнивает его runtime HMENU с raw source query и Qt projection.
Он пишет в `build/dev/ui-reports/` два `native-system-rendered-*.json` с rows,
font/DPI/style и два affected PNG при `SEVENZIP_CAPTURE_SCREENSHOTS=1`.
Этот comparator относится только к System popup и не заменяет общий capture
выше. Другая машина/DPI требует своей серии. Приёмка и observed adaptations —
в [parity](7zfm-parity.md) и [audit](upstream-port-audit.md).

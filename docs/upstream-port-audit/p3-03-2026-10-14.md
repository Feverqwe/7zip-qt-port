### Environment and isolation

The Linux readiness helper initially timed out because Hyper-V reported no IP.
Host ARP resolved the recorded address to the VM's exact MAC; pinned SSH trust
and guest identity were then verified. The active kernel lacked its matching
`linux-cloud-tools-6.8.0-146-generic`, so KVP exited2. Installing that package
and its versioned dependency restored KVP and the ordinary readiness helper.
Xorg/fbdev/libinput/xinit/X11 utilities and PCManFM dependencies supplied the
missing native console capability. Apt simulations and actual installs report
18 new packages, zero upgrades/removals. No disk was created/attached, and no
network, account, login policy or shared compiler/Qt configuration was changed.

Temporary Xorg and desktop services are limited to two hours. Xorg has a private
Xauthority and no TCP listener; desktop/receiver processes run with UID runner.
The package and receiver share a private DBus session and isolated HOME/config/
data directories. All input, output, archive and temp paths are under the owned
`/home/runner/sevenzip-desktop/native-acceptance-20261014` directory. The first
user-service experiment ended with SSH logout; root-managed transient services
with UID runner keep the tested session alive without enabling user lingering.

The Windows runner was also logged in normally through its observed Runner
password form and the existing host-local DPAPI credential. Guest CIM confirms
Explorer in Session1, AutoAdminLogon0 and no DefaultPassword value. No password
was printed, transferred to the Mac or written to a new file/registry value.
This restores capability for Windows acceptance; it is not a Windows full-gate
or rendered-product result.

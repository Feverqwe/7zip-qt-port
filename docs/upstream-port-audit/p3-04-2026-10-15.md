## P3-03/P3-04 — Linux default association Apply, Clear and identity (2026-10-15)

The native workflow in the [preceding receipt](p3-03-2026-10-15.md) found
that System Clear returned success while retaining Sevenzip Desktop as7z's
default. GIO removes supported types but keeps the Default Applications key.
The Linux platform adapter now removes only its own desktop ID from that MIME
type's current-user default list before the ordinary GIO removal. Other desktop
IDs keep their order, unrelated types remain intact, and the GFile replacement
uses the loaded etag; a changed etag returns the existing retry status1237.
GIO still owns supported-type mutation and database invalidation. This is not
an atomic transaction across both steps; native errors can follow a partial
change, as already documented for association Apply. No global/reset-all API
is used, and higher-level system/desktop association policy is not rewritten.

The same scenario exposed an identity problem with quoted desktop Exec paths.
GLib2.80's executable accessor takes a space-delimited first word without
unquoting it. The adapter now uses native argument parsing without executing
a shell, then compares canonical executable paths as before. A verified own
registration reports the source page's OwnIconPath, so a quoted/symlinked path
is not incorrectly shown as another `[7-Zip]` installation. A desktop entry
pointing to a different executable still cannot mutate associations.

### Source and dependency scope

7-Zip baseline remains https://github.com/ip7z/7zip.git at
`0766b733fe3e06dd2a7f9a3cfbf2108ac73abd17`. Reviewed complete
`CPP/7zip/UI/FileManager/SystemPage.cpp::CSystemPage::OnApply`, source state
cycle and callers, `SystemPage.h::CModifiedExtInfo::SetState`, and
`RegistryAssociations.cpp::DeleteShellExtensionInfo` with its declaration and
consumers. Those Windows registry operations have no usable Linux MIME service;
their ported page/service control flow remains authoritative. Changes are
confined to the existing native Linux boundary, tests and CMake registration.
No upstream body or new dependency was copied; no revision, license or
source-language boundary changed. The narrow adapter uses existing GLib/GIO
APIs, not another archive implementation or a replacement association page.

Primary native reference is [GLib2.80 gdesktopappinfo.c](https://github.com/GNOME/glib/blob/2.80.0/gio/gdesktopappinfo.c):
`binary_from_exec`, `g_desktop_app_info_load_from_keyfile`,
`update_mimeapps_list` and `g_desktop_app_info_remove_supports_type`.
[GIO remove_supports_type](https://docs.gtk.org/gio/method.AppInfo.remove_supports_type.html)
does not promise default removal;
[reset_type_associations](https://docs.gtk.org/gio/type_func.AppInfo.reset_type_associations.html)
would reset other applications' changes and is unsuitable here. These bodies
were inspected as native integration evidence, not copied into the port.

# Адаптивные цвета интерфейса

Дата: 2026-10-18. Запрошенная пользователем Qt presentation адаптация.

Upstream: [ip7z/7zip](https://github.com/ip7z/7zip/tree/9128b80e3a471108678e2b3ec3c985861c8d7b0f),
commit `9128b80e3a471108678e2b3ec3c985861c8d7b0f`.
Сверены `CPP/7zip/UI/FileManager/PanelListNotify.cpp::OnCustomDraw`,
`PanelSelect.cpp::UpdateSelection`, `AboutDialog.cpp/.h/.rc` и
`HelpUtils.cpp::ShowHelpWindow`, их Qt consumers и исходные цветовые токены
официального CHM CSS. Bodies соответствуют прежнему baseline
`0766b733fe3e06dd2a7f9a3cfbf2108ac73abd17`; baseline файлов сохраняется.

Upstream задаёт розовую отметку и красный текст удалённого файла непосредственно
в Win32 custom draw; Help использует HtmlHelp/hh.exe. Пригодной реализации
семантических цветов для Qt и смены палитры в этих модулях нет.
Новый `qtsemanticcolors` ограничен presentation: системная QPalette остаётся
источником фона, текста и выделения. Подложки выводятся из фактического фона,
акценты корректируются для контраста обычного текста. Дополнительные зависимости —
только уже используемые Qt Widgets/Gui и стандартная математическая библиотека.

`QtPanelList` передаёт состояние отметки, а `ArchiveTableItem` вычисляет её
BackgroundRole при чтении текущей палитры. Исходные решения о выборе и удалённых
элементах остаются у CPanel. Делегат учитывает фон системного выделения для
цветного текста; таблица и значки используют общий делегат.
About сохраняет ранее согласованную структуру, действия и тексты;
его подложки и ссылки обновляются при PaletteChange.
В списке временных файлов цвет защищённой строки также берётся из текущей
Disabled-палитры при чтении, вместо сохранения устаревающей кисти.

Справка использует Window/WindowText: фон документа, таблиц и viewport совпадает
с окном, подложки команд и заголовков выводятся из него. Цветовые токены
исходного CSS остаются точками подстановки; сами HTML/CSS resources не меняются.
Навигация, история, позиция прокрутки и обработка ссылок сохраняются.
Это продолжает [адаптацию справки](help-theme.md) и
[оформление About](about-product-identity.md).

Нового upstream functional code не копировалось. Алгоритмы выбора файлов,
проверка deleted property и исходные ветви команд не меняются и не опускаются.
Нативные контролы продолжают использовать стиль и палитру Qt; фиксированные
цвета оригинальных пиктограмм не перекрашиваются. Это адаптация цветов,
а не заявление о пиксельном совпадении с Windows 7zFM.

успешна. Focused CTest `help_source`, `help_ui`, `panel_deleted_draw`, `panel_key`,
`panel_refresh_completion`, `panel_cell_text`, `temp_cleanup`,

Регрессии проверяют смену уже открытой палитры: светлый, тёмный и цветные фоны,
читаемость обычного/выделенного удалённого файла, сохранение отметок,
фон справки как у окна, контраст таблиц/команд/ссылок и обновление About.
В существующих тестах точный розовый RGB заменён проверкой видимости отметки;
source-level deleted policy остаётся отдельно покрыта.

Нативный Cocoa-прогон Help palette/navigation, About live palette и EN/RU
normal/compact identity geometry — PASS (7 QtTest cases с init/cleanup).
Отдельный Cocoa-прогон live marks/deleted-text — PASS (3 с init/cleanup).
Проверены current-build widget JSON справки 760×560/420×300 и About;
нативные отчёты: `build/dev/adaptive-theme-review/`.
Первый Cocoa-запуск в sandbox не имел доступа к экрану; успешные проверки
выполнены вне sandbox. Переключение системных настроек ОС не проверялось:
сценарии меняют QPalette уже открытых нативных окон.
Windows/Linux, full/slow gates и rendered Windows 7zFM reference не проверены.

## Расширение на все окна

По последующему запросу пользователя scope расширен на весь интерфейс с отдельными коммитами
завершённых итераций и полным каталогом снимков окон для ревью.
Первая итерация общей палитры — `a8d5126`.

Исходники остальных Qt-окон, embedded pages и popup consumers сверены
вместе с существующими UI specifications. Они используют нативные роли Qt;
добавлять поверх них глобальный stylesheet или собственную светлую/тёмную
палитру не требуется. Оригинальные многоцветные значки остаются artwork,
а не заменяются одноцветными пиктограммами темы.

Обнаружен отдельный пробел в компактной строке состояния: elided paint
принудительно выбирал Active-цвет даже у неактивного окна. Теперь используется
текущая группа палитры QWidget, как у обычного QLabel. Регрессия рисует
неактивную и отключённую строку с различающимися системными ролями.
Сверены исходные `CPP/Windows/Control/StatusBar.h`,
`CPP/7zip/UI/FileManager/PanelListNotify.cpp::Refresh_StatusBar` и локальные
callers QtStatusLabel. Источник — тот же upstream commit, указанный выше.
Win32 StatusBar сам выбирает системное оформление; алгоритм вычисления
статистики и его source body не меняются. Дополнительный исходный код не копировался.

Нативный светлый Cocoa-прогон воспроизвёл нечитаемый красный текст на сером
неактивном выделении: делегат корректировал HighlightedText по активному синему
Highlight и применял результат ко всем группам. Теперь каждая группа получает
тон относительно собственного Highlight. Существующий rendered regression
обнаружил ошибку до исправления и прошёл после него в обеих схемах.
About и Help также учитывают активацию окна; проверка с различающимися
Active/Inactive палитрами сохраняет текст/тему справки и читаемые подложки About.

Для пользовательского ревью используется
[каталог сценариев](../../scripts/config/ui-review.json) и
`python3 scripts/capture-ui-review.py`. Он собирает существующие targets
инкрементально и снимает их UI-сценарии с нативным QPA в двух схемах.
Переключение через [QStyleHints](https://doc.qt.io/qt-6.12/qstylehints.html#colorScheme-prop)
действует только внутри процесса; настройки ОС
не меняются. Requested/effective scheme и фактическая палитра записываются в JSON.
Сценарии без снимков, с ошибкой или неподдержанной схемой отмечаются незавершёнными.
Состав окон/состояний хранится в каталоге сценариев, без второго списка в README.
По умолчанию галерея и manifest сохраняются в `build/dev/ui-theme-review/`.
Снимки показывают клиентскую область собственных Qt-окон; системные панели выбора
файлов и рамки/заголовки ОС не входят в этот каталог.

### Итоговая локальная проверка расширенного scope

macOS arm64 / Qt 6.12: все 34 группы нативного каталога завершены в light/dark
(68 запусков), получены 1058 PNG и соответствующие widget JSON.
Галерея `build/dev/ui-theme-review/index.html` фильтруется по окну, теме и строке
поиска; manifest сохраняет результаты и доступную информацию о ревизии/working tree.
Проверены целостность PNG/ссылок и синтаксис JS, просмотрены представительные
виды справки, About, Settings/System, прогресса, списков и выделения.
Это материал для запрошенного пользовательского ревью, а не утверждение о
просмотре каждого состояния или пиксельной идентичности оригиналу.

Focused CTest scope расширен до `help_source`, `help_ui`, `main_shell`,
`panel_deleted_draw`, `panel_key`, `panel_refresh_completion`, `panel_cell_text`,
`temp_cleanup`, `source_browse_dialog`, `ui_geometry`, `language_standard_buttons`
и `progress_dialog` — PASS (12 suites, включая профильные повторы после правок
тестовых обработчиков). Дополнительно пройдены нативные проверки inactive About/Help,
live palette/navigation и inactive/disabled status label.

При прогоне выявлены зависимые от английских слов проверки Copy и временных
файлов на фоне параллельной миграции переводов. Copy теперь проверяет реально
показанные выбранные имена с учётом Unicode normalization и исключает невыбранное;
scope guard закрывает диалог даже при провале проверки. В temp проверяются
предупреждение, отсутствие внешнего открытия/перехода и правильный объект в
Properties, вместо английских слов blocked/Size. Полезное поведение сохранено;
исходники параллельной миграции не включаются в эту итерацию.

Сборка и проверки используют существующие build/cache и официальный runtime;
SFX-съёмка также использует его, вместо случайного системного 7zz иной версии.
Windows/Linux runtime, OS-owned pickers, full/slow gates и Windows rendered
reference в этом расширении не запускались.

## Контраст выбранных style colors — 2026-10-18

Последующий Windows gate выявил хрупкую проверку manual delegate paint:
она требовала контраст 4,5 от пикселей растрированного текста относительно
заданного фона. Сглаживание и native paint меняют пиксели по краям glyph;
на Windows максимум в таком фрагменте составлял 4,02. Обычные rendered
табличные/иконные сценарии при этом проходили. Дополнительный частный фрагмент
300×40 использован для диагностики; минимальный Qt reproducer не создавался.

Теперь существующий panel_deleted_draw проверяет итоговые HighlightedText /
Highlight, переданные реальным делегатом в публичный QStyle::drawControl.
Тестовый proxy владеет отдельной копией исходного style и принадлежит view;
глобальный application style ему не передаётся во владение. Цветовые группы
Active/Inactive/Disabled имеют разные фоны и должны сохранять красный акцент
с контрастом не ниже 4,5. Обычная отрисовка таблицы/значков, обе панели,
EN/RU и варианты выделения остаются в прежних rendered scenarios.
Производственные цвета и исходный OnCustomDraw этой коррекцией не менялись.

Набор целиком прошёл на macOS arm64 (3,75 с), Linux x64 (1,98 с) и Windows x64
(7,77 с), Qt 6.12; guest run `20261018T150811Z-85d6e3ed`. Использованы прежние
build trees и compiler caches. Временный diagnostic launcher удалён локально и
из current guest при синхронизации. Это адресное закрытие сбоя регрессии,
без утверждения полного визуального паритета с оригинальным 7zFM.

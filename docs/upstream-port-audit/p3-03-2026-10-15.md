`0766b733fe3e06dd2a7f9a3cfbf2108ac73abd17`. Reviewed original
`CPP/7zip/UI/FileManager/PropertyName.cpp::GetNameOfProperty`, its declaration,

`App.cpp::CApp::ReloadLangItems`. The original property helper localizes known
IDs and falls back to the supplied provider name before numeric IDs. The
existing port already stores that authoritative descriptor; the Qt language
adapter now passes its name to the same helper. No upstream body, algorithm,
dependency, revision or source-language boundary is replaced or newly copied.
Raw-property handling and provider/catalog ownership are unchanged.

## P3-04 — Native Linux GIO default-open and unfinished Clear (2026-10-15)

The same Linux delivery identified in the previous receipt was tested with a
private XDG profile and a fixture desktop entry pointing to its exact executable.
Without that installed entry the source System page correctly disables mutation.
Pending association Cancel left the default absent. Applying only7z registered
the private default; native `gio open` launched the packaged7zFM with the exact
Unicode/spaced archive argv. The owned mapped window was inspected: archive
rows, packed sizes and CRC columns were populated, and archive SHA was unchanged.
This is a real Xorg/GIO launch; no global desktop entry/default was installed.

Clear exposed a further defect: after source Apply, GIO reports no registered
applications but still returns Sevenzip Desktop as the default. The adapter calls
`g_app_info_remove_supports_type`, which removes support rather than guaranteeing
default removal. Clear/restore is not accepted and requires a separate integrated
native-association correction preserving other applications' preferences.
The private profile and evidence are retained for that correction.

Local evidence is in `build/review/final-availability-8e9343b-20261014`, including
the GIO launch argv/window proof, affected-window captures, failed Clear query,
Windows full logs and service diagnostic ZIP. Hyper-V Linux thumbnails became
black despite a live Xorg display; affected-window XGetImage captures were then
used with an exact owned7zFM PID/executable guard. Two-hour transient service
expiry interrupted the first GIO attempt; only the renewed, mapped and inspected
launch is counted. Full native/rendered reference, clean OS, stable Windows,
current packages after code changes and macOS Computer Use remain unaccepted.

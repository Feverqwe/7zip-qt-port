# Последовательная миграция проекта на основу C++23

## Цель

Перевести все компоненты Sevenzip Desktop на единую основу сборки C++23:
явные зависимости между targets, управляемые зависимости, проверяемые границы
владения и времени жизни, статический анализ и санитайзеры. Сохранить поведение
приложения, независимую сборку форка 7-Zip и происхождение заимствованного кода.

Готовая конфигурация стандарта сама по себе не завершает миграцию компонента:
его производственные потребители, тесты и поставка должны использовать ту же
реализацию и согласованные настройки.

## Границы

- Форк 7-Zip остаётся самостоятельным проектом. Его алгоритмы и control flow
  сохраняются; C остаётся C. Обновления сборки и адаптеров следуют существующему
  [source audit](upstream-port-audit.md) и правилам сравнения с upstream.
- Внешние C-библиотеки предоставляют C++23 named modules через фасады.
  Собственный C++ получает модульные интерфейсы на подходящих границах;
  необходимость совместимых заголовков для Qt/moc и платформенных API учитывается
  явно. Перенос не требует превращать каждый класс Qt в named module.
- Современные типы владения, `span`, `expected`, ranges и monadic operations
  применяются в локальной интеграции там, где выражают её контракт и устраняют
  конкретный риск. Сокращение числа строк не является основанием переписывать
  заимствованные алгоритмы или менять наблюдаемое поведение.
- Существующие [архитектурные границы](architecture.md), лицензии и единая
  реализация архивных операций сохраняются. Политики разработки и проверки
  остаются в [AGENTS.md](../AGENTS.md), а не дублируются в этом плане.

## Порядок

1. Завершить приёмку основы: полные manifest-сборки Linux и Windows,
   проверки прямых потребителей и ограничения сочетаний компилятора,
   module BMI и clang-tidy. Уже выполненные проверки не повторять без причины.
2. Общие библиотеки и контракты: выделить согласованные настройки targets,
   зависимости C/C++, небольшие типы данных и границы владения. Подключать
   каждый перенесённый интерфейс к реальным потребителям в той же итерации.
3. Backend и операции: последовательно перевести ввод/вывод, ресурсы архивов,
   асинхронные операции и их платформенные адаптеры, сохраняя владельцев
   состояния, отмены и ошибок.
4. UI и интеграция Qt: переводить завершённые компоненты и их backend-связи,
   сохраняя команды, сигналы, состояние и правила работы moc.
5. Точки входа и инструменты: согласовать приложение, отдельные native helpers,
   тестовые потребители, установку и упаковку с перенесёнными компонентами.
6. Завершить переход: убрать замещённые пути сборки и дублирование после
   проверки их потребителей; зафиксировать только необходимые исключения.

Порядок внутри этапа определяется зависимостями из текущего исходного кода.
Этот план не создаёт второй каталог файлов, символов или upstream-долга.

## Завершение итерации и всей цели

Итерация охватывает работающий компонент с его потребителями, целевыми
проверками поведения и необходимыми изменениями поставки. Завершённые итерации
фиксируются отдельными коммитами. Проверки используют существующие
инкрементальные деревья и кеши; недоступный runner не останавливает независимую
работу, а непроверенная платформа отмечается явно.

Цель завершена, когда все производственные компоненты, тесты и инструменты
используют согласованную основу, отсутствуют неподключённые новые интерфейсы
и замещённые параллельные реализации, а затронутые сценарии проверены на macOS,
Linux и Windows. Обязательства по полноте переноса исходников и по runtime
проверке оцениваются отдельно. Ограничения анализатора не выдаются за гарантии
проверки заимствований уровня Rust.

# Приёмка и границы UX-сверки

Обязательный Qt-план завершён 2026-10-17. Полный результат с ревизиями,
исходными сбоями и последующими проверками — в
[итоговой приёмке](archive/qt-port/ux-port-audit.md#final-acceptance-of-product3a0b3b7).
Эта запись подтверждает согласованный объём той версии; новые изменения
проверяются по затронутому сценарию.

## Сохранённые границы

- Полнота source port и runtime-проверки оценены отдельно.
- Native-сценарии проверены в указанных состояниях на трёх ОС; геометрия
  и widget JSON не подтверждают равенство пикселей или весь OS workflow.
- Первое выполнение подготовленных Windows binaries после перезагрузки
  принято в записанных пределах. Причина прежних задержек loader/process
  не установлена; не заявляется неограниченная стабильность времени запуска.
- GitHub/public CI, clean-OS и новые VHD-сценарии исключены из той приёмки.
  Долгий `copy_archive_refresh` не выполнялся; остальные long receipts
  сохраняют собственные ревизии и scope.
- Защищённый выбор default app в Windows Settings остался непроверенным.
  Ручная Finder-проверка и native startup regression имеют разные свидетельства.
- Проверены локальные пакеты; публичное распространение, Developer ID,
  notarization и Authenticode не входят в тот результат.

## Работа с новым UI-изменением

Сначала прочитать исходные ресурсы, handlers и callers затронутого вида.
Использовать [действующие спецификации](ui-layout-contracts.md),
[geometry-проверки](testing/geometry.md) и при необходимости
[native runtime comparison](ui-runtime-comparison.md).
Необходимые отличия Qt/ОС описывать в [parity](7zfm-parity.md).

Историческая [UX-матрица](archive/qt-port/ux-port-audit.md) сохраняет исходные
открытые замечания и их закрытие. Она не служит очередью новых задач.
Новый баг или source gap фиксировать по конкретному сценарию и owner;
свидетельства проверки связывать из [source audit](upstream-port-audit.md).

# План развития Sevenzip Desktop

Цель: постепенно перенести интерфейс и рабочие сценарии Windows 7-Zip File Manager (`7zFM`) в кроссплатформенное приложение на Qt Widgets. Наш репозиторий содержит C++17/Qt 6 Widgets UI и адаптер; официальный 7-Zip остаётся в соседнем `../7zip-upstream`. Текущий адаптер запускает официальный `7zz` через `QProcess`.

## Ориентир для интерфейса

- Повторять структуру и смысл Windows 7-Zip File Manager: меню, панель команд, адресную строку, таблицу файлов, навигацию, основные диалоги и сочетания клавиш. Новые элементы не придумывать для функций, уже имеющих понятный аналог в Windows 7-Zip.
- Перед реализацией каждого UI-этапа сверять его с оригиналом: исходники и ресурсы `../7zip-upstream/CPP/7zip/UI/FileManager/`, а также проверенные снимки Windows-приложения, когда они доступны. В PR или отчёте указывать, что совпадает и почему отличается.
- На macOS и Linux сохранять узнаваемую компоновку Windows-версии. Нативные системные диалоги, масштабирование, доступность и особенности ОС могут отличаться; такие изменения фиксировать отдельно. Пиксельное совпадение между ОС не является критерием готовности.

## Как идти по плану

- Выполнять этапы по порядку, но брать за одну задачу один небольшой результат из очередного этапа. После него обновлять статус здесь и фактические возможности в README.
- Сначала проверить существующий код и тесты: отметка «готово» означает проверенное поведение, а не только написанный код.
- Для нового поведения добавлять тест, который проверяет видимый результат; для ошибок — тест, воспроизводящий ошибку. Запускать `./scripts/check.sh` и просматривать снимки из `build/dev/ui-screenshots/` при изменениях интерфейса. Снимки сейчас **не сравниваются автоматически**.
- Указывать, на каких ОС результат действительно проверен. Локальный macOS тест не подтверждает работу Windows и Linux. Когда появится GitHub remote, использовать существующий CI на трёх ОС и разбирать его результаты до заявления о кроссплатформенной готовности.
- Сохранять границу компонентов: UI не формирует аргументы `7zz`; `../7zip-upstream` служит источником и справочником, но не местом для наших изменений. Новые команды оставлять отключёнными до реализации и проверки.
- Не совмещать крупный рефакторинг, новую функцию и упаковку релиза в одну задачу. В конце каждого этапа приложение должно собираться и выполнять прежние сценарии.

## Точка отсчёта — MVP (готово локально на macOS)

- [x] Отдельный Git-репозиторий UI и соседний checkout официального 7-Zip.
- [x] Qt Widgets, CMake presets, проверки форматирования и CTest.
- [x] Открытие и просмотр `.7z`/`.zip`, создание нового архива, извлечение всего или выбранного, прогресс и отмена.
- [x] Backend-тесты с временными архивами и тест геометрии окна в трёх размерах со снимками.
- [ ] Подтвердить текущий MVP на Windows и Linux. Пока это не сделано, статус всех платформ — «не проверено».

## Этап 1. Укрепить текущие сценарии

**1.1. Предсказуемое состояние окна.** Выделить управление доступностью команд и состояниями «нет архива / загрузка / просмотр / операция / ошибка». Проверить тестами, что повторное открытие, ошибка запуска `7zz`, отмена и пустой архив оставляют окно в корректном состоянии. Команды не должны запускаться повторно во время операции.

Статус: **готово локально на macOS**. Состояния и доступность команд вынесены в `MainWindow`; Qt тест проверяет повторное открытие, пустой архив, реальную ошибку запуска `7zz`, отмену загрузки и извлечения, а также запрет повторного запуска во время операции. `./scripts/check.sh` прошёл; снимки трёх размеров осмотрены. Windows и Linux ещё не проверены. Структура меню, панели и таблицы сохранена; отличие в системных диалогах Qt остаётся платформенной адаптацией.

**1.2. Прогресс и журнал операции.** Показывать название операции, текущий файл или действие и результат без потери ошибок. Добавить доступный из окна журнал последней операции. Проверить неполный вывод `7zz`, ошибку, отмену и крупный архив; длительная операция не должна блокировать UI.

Статус: **готово локально на macOS**. Вывод `7zz` разбирается по завершённым строкам, включая фрагменты между чтениями и последний фрагмент без перевода строки; журнал доступен из меню «Файл» во время операции и после неё. Диалог прогресса показывает операцию, текущий файл или действие и процент, а итог и ошибки остаются в журнале. Проверены фрагментированный вывод с ошибкой, отмена, пустой архив и список из 3000 записей с проверкой работы таймера UI. `./scripts/check.sh` прошёл, снимки окна и журнала осмотрены на macOS. Большие архивы сверх тестового примера, а также Windows и Linux требуют проверки. Ориентир Windows `7zFM` показывает имя текущего файла и сообщения в диалоге прогресса; отдельная команда журнала в меню — адаптация Qt для доступа к выводу во время и после операции.

**1.3. Безопасность извлечения.** Проверить и при необходимости усилить обработку абсолютных путей, `..`, ссылок, конфликтов имён и путей с Unicode на всех ОС. Не извлекать архив, если путь назначения или содержимое небезопасны. Тесты используют только временные каталоги.

**Готово, когда:** базовые операции проходят `./scripts/check.sh`, ошибки видны пользователю, отмена оставляет рабочее окно, а README описывает реальные ограничения.

## Этап 2. Проверить три платформы до расширения функций

**2.1.** Подключить GitHub remote и запустить существующие macOS/Linux/Windows CI проверки. Исправить платформенные ошибки сборки, поиска `7zz`, путей и кодировок. Не считать зелёную локальную проверку заменой CI.

**2.2.** Сделать короткий ручной чеклист для каждого рабочего стола: запуск, открытие, создание, извлечение, отмена, длинный путь, Unicode, компактное окно. Сохранять снимки интерфейса для осмотра; эталоны и автоматическое сравнение пока не вводить.

**Готово, когда:** один и тот же тестовый набор зелёный на трёх ОС, а ручной чеклист пройден хотя бы на одной реальной среде каждой ОС. Если доступен только CI, отметить ручную проверку как ожидающую.

## Этап 3. Файловая навигация как в 7-Zip File Manager

**3.1.** Показать файловую систему: текущий каталог, список файлов и папок, переход в папку и назад, адресную строку. Открытие архива из списка должно сохранять понятный путь возврата.

**3.2.** Внутри архива добавить переход по каталогам и «вверх», сортировку по столбцам и выделение нескольких объектов. Строки каталога и файла должны вести себя по-разному. Сохранить поддержку пустых папок и длинных имён.

**3.3.** Добавить основные клавиатурные действия (Enter, Backspace, Ctrl/Cmd+O, выбор всех), не меняя привычную структуру окна без причины.

**Готово, когда:** пользователь может пройти файловую систему, открыть архив, пройти его дерево и вернуться без диалогов для каждого шага; навигация покрыта тестами модели/состояний и проверена снимками в трёх размерах.

## Этап 4. Создание и изменение архивов

**4.1.** Сделать единый выбор файлов и папок для создания нового архива. Перед запуском показывать формат, имя, место сохранения и набор источников; отмена не оставляет повреждённый целевой файл.

**4.2.** Реализовать добавление к существующему архиву отдельно от команды «Создать». Проверить конфликт одинаковых имён, вложенные папки, Unicode, файл больше нескольких мегабайт и ошибку записи.

**Готово, когда:** команда «Добавить» однозначно работает с открытым архивом или создаёт новый по явно выбранному сценарию; содержимое после операции перечитывается и совпадает с ожидаемым.

## Этап 5. Извлечение и проверка содержимого

**5.1.** Улучшить выбор назначения, правила перезаписи и сообщения об ошибках. Для выбранных файлов сохранять структуру путей в архиве. Проверить пустой выбор, уже существующие файлы, недоступную папку и отмену.

**5.2.** Включить команду «Тест» через официальный `7zz` и показать результат проверки без извлечения файлов.

**5.3.** Добавить «Информация»: формат, размеры, число файлов и доступные свойства без догадок по неполному выводу `7zz`.

**Готово, когда:** извлечение и тест архива дают понятный итог, не скрывают частичные ошибки и имеют интеграционные тесты для `.7z` и `.zip`.

## Этап 6. Пароли

**6.1.** Добавить запрос пароля для открытия, проверки и извлечения защищённых архивов; отличать неверный пароль от повреждённого архива там, где это позволяет `7zz`.

**6.2.** Добавить пароль при создании архива с явным выбором доступного режима шифрования. Не сохранять пароль в настройках, логах, снимках и сообщениях об ошибке; проверить путь передачи секрета в `7zz` на каждой платформе до включения функции.

**Готово, когда:** защищённый архив можно создать и открыть, неверный пароль обрабатывается без утечки, отмена работает, а тесты не содержат реальных секретов.

## Этап 7. Остальные команды файлового менеджера

**7.1.** Копирование и перемещение между файловой системой и архивом. Для каждой пары источника и назначения определить поведение и запретить неподдерживаемые комбинации.

**7.2.** Удаление и переименование: подтверждение, понятная область действия, обновление списка после операции и безопасное поведение при ошибке. Добавлять эти команды по одной.

**7.3.** Перетаскивание файлов в окно и из него там, где это поддерживает ОС; контекстное меню и сочетания клавиш для уже реализованных действий.

**Готово, когда:** каждая включённая команда имеет проверенный сценарий успеха, ошибки и отмены; неподдерживаемые действия недоступны в UI.

## Этап 8. Выпуск приложения

**8.1.** Подготовить сборки и упаковку для Windows, macOS и Linux; решить способ поставки официального `7zz` или установки зависимости. Зафиксировать версию/коммит upstream для каждого выпуска.

**8.2.** До распространения выбрать лицензию нашего UI и проверить лицензионные условия Qt и 7-Zip для выбранного способа поставки. Добавить сведения о лицензиях в пакеты.

**8.3.** Проверить установку, запуск, обновление и удаление на чистых системах; выпускать версии с чеклистом регрессий и известными ограничениями.

**Готово, когда:** пользователь может установить сборку на всех трёх ОС и выполнить ключевые сценарии без ручной настройки среды разработки.

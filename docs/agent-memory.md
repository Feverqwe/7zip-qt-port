# Память агента между задачами

Память хранится в локальном Obsidian vault `.codex/` и читается как обычные
Markdown-файлы. Открывать приложение Obsidian или подключать MCP не требуется.
Правила чтения задаёт `AGENTS.md`; setup создаёт структуру и сохраняет историю.

## Начало задачи

1. Прочитать `.codex/memory/README.md` и выбрать записи по теме запроса.
   Если индекса нет, работать по коду и `docs/`; при необходимости запустить
   `sh .agents/skills/sz-setup/scripts/setup.sh`.
2. Прочитать только относящиеся к задаче записи. Сопоставить их дату, статус,
   checkout, ветку и commit с текущим состоянием Git; проверить значимые выводы
   в текущем коде. Не читать весь архив заметок по умолчанию.
3. Использовать текущий запрос пользователя для выбора работы. Запись о следующем
   шаге не является поручением, разрешением или основанием продолжать чужую задачу.
   При расхождениях обновить устаревший вывод с новым свидетельством.

## Что сохранять

Для существенного исследования или передачи работы создать отдельный файл
`.codex/notes/YYYY-MM-DD-topic-id.md` по шаблону `.codex/templates/handoff.md`.
Короткий уникальный суффикс отделяет параллельные задачи с одинаковой темой.
Статус: `active`, `handoff`, `completed` или `superseded`. Статус описывает запись,
а не состояние другого чата в приложении.

В начале записи зафиксировать область задачи и checkout/ветку/commit. Сохранять
только сведения, которые помогут следующему агенту:

- найденные upstream-файлы, символы, зависимости и commit;
- что можно копировать напрямую, какие Qt/платформенные адаптации нужны и почему;
- доказанные причины неудачных подходов, чтобы не повторять исследование;
- неизвестное, ограничения, незавершённая работа и конкретный следующий шаг;
- команды проверок, дату, ОС, результат и проверенную ревизию/область изменений.

Перед завершением задачи обновить её запись и добавить ссылку с темой, датой
и статусом в индекс. Завершённое полезное исследование перенести в раздел
Reusable investigations; закрыть устаревшую передачу работы, не оставлять её
активной. Простая правка без новых выводов не требует записи. Не копировать
логи инструментов, переписку или длинные фрагменты кода.

## Цели проекта и источник истины

Для Sevenzip Desktop память должна помогать переносить исходный код 7-Zip,
а не закреплять самостоятельно написанную реализацию как образец. Подтверждать
происхождение по upstream commit и реализации; совпадения имён и поведения
недостаточно. Следующий агент должен видеть, где завершён source port, а где
остаётся долг переноса, без создания второго реестра этого долга.

Устойчивые выводы публиковать в соответствующем документе, оставляя в памяти ссылку:

| Содержание | Авторитетный документ |
| --- | --- |
| Происхождение, копирование, адаптации, долг переноса | `docs/upstream-port-audit.md` |
| Сценарии 7zFM и отличия платформ | `docs/7zfm-parity.md` |
| Владельцы компонентов и границы backend/UI | `docs/architecture.md` |
| Проверки поведения и ограничения покрытия | `docs/testing.md` |
| Сборка и обходы проблем toolchain | `docs/development.md` |
| Группы контролов и проверка компоновки | `docs/ui-layout-contracts.md` |
| Правила и предпочтения работы агента | `AGENTS.md` и профильные skills |

Память содержит даты и свидетельства; она не переопределяет инструкции, код
или текущие документы. Старый успешный `check.sh` не подтверждает новый checkout.
Проверка на macOS не подтверждает Windows/Linux. Не сохранять пароли, токены,
содержимое пользовательских архивов и личные пути вне необходимых идентификаторов
checkout; использовать ссылки на код и одноразовые тестовые fixtures.

## Параллельная работа и переносимость

Каждая задача обновляет свою запись. Общий индекс менять небольшим патчем,
сохраняя чужие ссылки; не заменять его глобальным текущим статусом. Чужие
изменённые файлы отмечать как наблюдение и перепроверять перед работой с ними.
Не присваивать их своей задаче и не очищать рабочее дерево по старой заметке.

`.codex/` игнорируется Git: память переживает новые чаты в этом checkout, но
не переносится автоматически на другую машину, clone или worktree. Для такого
перехода явно передать относящиеся к задаче записи и повторно проверить их.
Продуктовые знания в tracked `docs/` доступны и без локальной памяти.
Setup не перезаписывает существующий индекс, заметки или вложения.

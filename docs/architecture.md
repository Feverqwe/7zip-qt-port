# Architecture

## Repository boundary

`sevenzip-desktop` owns the graphical application, platform integration, archive backend adapter, tests, and build configuration. `../7zip-upstream` is the unmodified official source checkout for reference and later integration work. The application must not depend on a fixed absolute path to that checkout.

## Components

```text
Qt Widgets (window, file list, dialogs)
          |
ArchiveBackend interface (operations, progress, errors)
          |
SevenZipProcessBackend (official 7zz executable)
          |
7-Zip original compression and format code
```

`src/archivebackend.h` defines archive entries, reported archive information and asynchronous operations. `src/archivebackend.cpp` owns command arguments, `7zz l -slt` parsing, progress, cancellation and errors. `src/mainwindow.h` owns dialogs, table presentation and the explicit filesystem / loading / viewing / operating states. The address bar and table show the current directory until an archive is opened. The window retains the complete archive listing and derives direct children of the current archive folder, including implicit intermediate folders and explicit empty folders. Table items retain full entry paths so sorting cannot change extraction targets. Selecting a folder expands to its listed descendants before calling the backend. Directory history and the source directory for an opened archive are kept in the window; a failed or cancelled listing restores the directory. All command availability is updated from these states and the table selection. A direct 7-Zip API adapter can replace this backend later.

The File menu offers Create Folder and Create File for the current filesystem directory. Create File uses an editable combo dialog patterned on `ComboDialog.rc`, creates an empty file without replacing an existing name, and selects it in the refreshed list. Edit provides selection commands, including case-insensitive wildcard matching and selection by the focused item's extension or folder type, following `PanelSelect.cpp`. View provides Refresh, which rereads the filesystem directory or starts a new asynchronous archive listing while commands are disabled. The archive refresh restores the internal folder and paths still present in the new listing; a failed or cancelled listing follows the normal return-to-directory behavior. These commands follow `7zFM` File/Edit/View placement and F7/Ctrl+N/Ctrl+R shortcuts. Folder and file name validation excludes separators and Windows reserved punctuation so created names remain portable. The main toolbar follows `7zFM`'s two groups: Add, Extract, Test, then Copy, Move, Delete, Info. Add opens new-archive creation in a filesystem folder and the existing-archive add dialog while viewing an archive. Back and Up sit beside the path field, following the separate navigation controls in the Windows panel header. The View menu exposes the four toolbar choices in upstream `resource.rc` and `App.cpp`: show each group, large buttons and button labels. They are stored in a local INI file through `QSettings`. Qt paints compact color glyphs matching the original bitmap symbols; it does not package upstream bitmap assets. The address is an editable combo box with the 20 most recently visited filesystem and archive roots persisted in that INI. The Alt+F12 history dialog lists these roots, supports removal, and navigates to a selected entry; unlike Windows `FoldersHistory()`, it does not list internal archive folders.

`7zFM`'s `PanelItems.cpp` puts Name first, defaults to a narrow property-column width, hides Packed Size for filesystem folders, and allows property-column customization from a header context menu. The Qt table now hides its internal full-path column, row numbers and grid, keeps Name elastic, and offers checkable Size, Packed Size and Modified header options. Packed Size is suppressed in filesystem mode; column choices persist in the same INI file. The path stays in item data for operations. `PanelMenu.cpp` builds the item context menu from selection and folder capabilities; the Qt context menu likewise distinguishes selection, filesystem and archive commands, with Create Folder and Refresh available from the background. Properties for one selected entry use filesystem metadata or the already listed archive entry, following `PanelMenu.cpp`'s selected-item property workflow. The current Qt dialog exposes the basic fields; the upstream dialog includes many more format-specific properties and supports aggregate metadata for multiple selections. Windows shell extensions and `7zFM`'s full File menu are not yet ported.

The View menu's sort commands follow `resource.rc`: Name, Type, Date, Size, and Unsorted, with Ctrl+F3–F7. Hidden table columns carry normalized type and source-order values; they do not appear in the file list. Rebuilding a filesystem folder records enumeration order, while rebuilding an archive folder records first appearance in the backend listing. Sorting remains selected across navigation and refresh within one window. The current implementation keeps folders before files even in Unsorted mode; full `PanelSort.cpp` property comparisons remain future work.

The backend separates `7zz` output into complete lines across process reads, emits progress and current-file detail, and forwards each line to the UI. The window keeps the complete log of the current or last operation, including the final result. Its nonmodal progress dialog leaves the main window and log available while commands remain disabled by the window state. The Windows `7zFM` progress dialog shows the operation and current filename and has a messages view; the Qt menu command exposes the same information without changing the file-list layout.

Creation starts from the filesystem state. A single Qt dialog starts with the filesystem selection and accumulates files and folders from directory listings and shows the source set, archive name, format and destination before submission. The backend writes a uniquely named temporary archive in the destination directory, then renames it to the requested path only after `7zz` exits successfully. Failure, launch error and cancellation remove that temporary file. Existing targets are rejected, and a target inside a selected source directory is rejected. The window refreshes its filesystem listing after creation ends. Windows `7zFM` starts Add to archive from a filesystem selection and presents an options dialog; the Qt dialog keeps that review step while allowing a mixed source set from multiple directories.

Adding is a separate command available while viewing an open archive, including an empty one. The same source picker shows a fixed target, format and destination. The backend requires a successful listing of that archive and rejects matching paths using case folding and Unicode normalization, as well as links and unsafe source names. It copies the archive to a temporary peer, runs `7zz a` on the copy, then moves the original to a backup and the updated copy into place. Failure or cancellation removes the copy and leaves the original; the backup is kept if rollback cannot restore the target. The UI disables commands through the update and follow-up listing, then displays the reread contents. Copying the existing archive currently runs on the GUI thread, so unusually large archives can pause the window before `7zz` starts. The original Windows Add command begins from filesystem selection; the separate open-archive command is a Qt workflow adaptation requested for stage 4.2.

Stage 7 retains the Windows toolbar order for Copy, Move and Delete, adds Rename to the File menu, and exposes the same actions in the table context menu. Action availability is derived from mode and selection. Filesystem-to-filesystem Copy and Move use a typed existing destination directory, reject occupied names, links and a destination inside a source directory, then refresh the directory listing. Copy stages each target under a temporary peer name before renaming it into place; Move uses rename and can fail across volumes. Filesystem deletion requires confirmation and refreshes the list even on error. These filesystem operations run on the GUI thread; cancellation is possible in the destination or confirmation dialog, not after a transfer begins. A multi-item filesystem delete can finish some items before a later item fails.

Archive-to-filesystem Copy reuses selected extraction and its safety checks. Filesystem-to-archive Copy uses the existing Add action or local-file drop. Archive-to-archive copy and any Move involving an archive are disabled. Delete for selected archive entries expands selected folders to their listed descendants; Rename is limited to one file in an unencrypted archive. The backend validates names against the current listing, copies the archive to a temporary peer, runs `7zz d` or `7zz rn`, and uses the same backup-and-replace sequence as Add. Success triggers a new listing; launch failure or cancellation leaves the original archive available. Drag-out of ordinary filesystem paths publishes local-file URLs; drag-in accepts only local-file URLs and always requests Copy. Native drag-out of archive entries is not implemented. This follows the Windows 7zFM command placement and selection-based availability; Qt's standard dialogs and URL drag protocol are platform adaptations.

## Functional target

The Windows 7-Zip File Manager (`7zFM`) is the UI and interaction reference. New Qt Widgets features should follow its window structure, commands, dialogs, and workflow; necessary platform deviations must be documented. The MVP implements filesystem listing and folder navigation, archive folder navigation, column sorting, multiple selection, new archive creation, addition to an open archive, extraction, test and archive information, plus the supported stage 7 commands above. The Qt editable path combo shows the archive path and current internal folder while browsing an archive. Back and Up are beside it. Double-clicking an archive file does not launch an external viewer yet. System integration remains disabled.

## Data and safety

Archive paths and filenames are runtime input. `QProcess` receives structured arguments, not a shell string. Before full extraction the backend checks every listed entry; for selected extraction it checks only paths passed to `7zz` and rejects absolute or parent paths, links reported by `7zz`, nonportable names, case or Unicode equivalent duplicates, and file/directory conflicts. It also requires an existing destination directory, rejects a final symlink, and rejects existing target files and symlink ancestors inside the destination. Existing directories may be reused; files are never overwritten. Extraction only starts after a successful listing of the same archive. For encrypted archives, a successful `7zz t` is required before extraction to avoid files left by a wrong password. This is a preflight check; concurrent external changes to the archive or destination can invalidate it before `7zz` writes.

The creation dialog follows the Windows 7-Zip Add to archive options with explicit encryption choices: `.7z` data AES-256 with optional header encryption, or `.zip` AES-256. The local `7zz` rejects Unicode ZIP AES passwords, so ZIP creation is limited to ASCII passwords. The window prompts when `7zz` requests a password for opening, testing or extracting, and keeps it only while that archive is open. The backend sends UTF-8 password bytes through the child process stdin using `-sccUTF-8`; the `-p` switch for creation contains no password. Secrets are absent from process arguments and redacted from forwarded output. Wrong-password diagnostics are distinguished only when `7zz` says so; other failures remain generic. Adding to an encrypted archive is disabled. The Windows UI uses its own password dialog and native callback; this Qt adaptation uses the official console process without changing the main window layout. Windows and Linux password transport still require CI and manual platform verification.

`7zz t` runs asynchronously through the same adapter and cancellation path, without a destination. The window enables Test and Info for an open archive, including an empty one, and disables them during loading and other operations. The Info dialog uses `Type` and `Physical Size` only when `7zz l -slt` reports them in the archive header. File and folder counts and total original file size come from parsed entries. The extraction dialog states the no-overwrite rule and allows a typed or browsed destination. These Qt dialogs adapt the Windows `7zFM` Extract, Test and Info workflows; the toolbar position and file-list layout remain unchanged.
